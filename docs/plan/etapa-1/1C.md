# 1C Render e adaptador Claude Code

> Trilha 1C da [Etapa 1](../plano-de-construcao.md#4-etapa-1-loop-mínimo-verificável-m0a). Componentes G1 e S4 (HG §3.2). Data: 01/11/2026. Status: **proposta**, aguardando revisão da pessoa.
> Branch `etapa-1/1C`, worker 2, em paralelo com a A. Fatos da ferramenta: [claude-code-facts.md](../etapa-0/claude-code-facts.md). Contrato: [hooks.md](../../contracts/hooks.md).
> **Pré-requisito:** o CI da Etapa 0 verde (ver [1A](1A.md)).

## Escopo

**Dentro:**

1. **`harness render [--target <repo>] [--tools claude-code]`**, idempotente. `data.changed` lista os arquivos que mudaram (vazio na segunda execução).
   - **AGENTS.md (G1).** Se não existe, é criado a partir de `core/templates/AGENTS.md` (1D, esqueleto com TODOs). Se existe, só o conteúdo entre `<!-- harness:begin boundaries -->`/`<!-- harness:end boundaries -->` e `<!-- harness:begin workflow -->`/`<!-- harness:end workflow -->` é reescrito. Se os marcadores não existem, insere o bloco BOUNDARIES logo depois do primeiro H1 e o Workflow no fim. Marcador órfão ou duplicado → `fail` (1) com `arquivo:linha`, sem escrever nada.
   - O **bloco BOUNDARIES** é montado a partir de `profile.boundaries`: cabeçalho em caixa alta, três listas **SEMPRE / PERGUNTE ANTES / NUNCA**, e cada `never` termina em `→ <instead>`. Os matchers não entram no texto. O **bloco Workflow** é o texto estático de `core/templates/agents-workflow.md` (1D, ≤ 10 linhas).
   - **CLAUDE.md.** Se existir sem `@AGENTS.md`, o resumo avisa ("o Claude Code lê só o CLAUDE.md; acrescente `@AGENTS.md`"), mas o arquivo não é tocado. No N0 (midcortes) não há CLAUDE.md, e o Claude Code lê o AGENTS.md nativamente (fatos §5).
   - **`.claude/settings.json`**, com merge que não perde nada: chaves desconhecidas, hooks de outros e regras de permissão do time ficam como estão. O harness acrescenta:
     - em `hooks.Stop`, um grupo cujo handler roda `harness hook stop_gate --adapter claude-code`, com `timeout: 60`. Os handlers do harness são reconhecidos pelo trecho `hook <nome> --adapter claude-code` e substituídos, nunca duplicados. **Só `Stop`**: um `SubagentStop` prenderia o verifier quando o gate está vermelho;
     - em `permissions.deny`, as regras `Edit(...)` para os insumos de aceite da ADR-0003 (`.harness/work/*/tasks.json`, `.harness/runs/**`, `.harness/profile.json`, `.harness/harness.lock`, `.harness/bin/**`, `.claude/settings.json`). `Write(path)` nunca casa (fatos §2). A forma exata do caminho (relativo, `/…` ou `//…`) sai do probe do item 4.
     - `never`/`ask` do perfil **não** viram regras nesta trilha: a compilação deles é da 3S. O resumo diz isso.
   - **Comando do hook na Etapa 1.** Ainda não existe `.harness/bin/harness` (é da 2B). O comando é `"<sys.executable absoluto>" "<clone>/bootstrap.py" hook stop_gate --adapter claude-code`, sem depender de bash (fatos §6, Windows). Esse caminho é da máquina de quem roda: a 1I registra isso como limite, e a 2B troca por `.harness/bin`.
   - **Sub-agents** `.claude/agents/harness-{implementer,verifier}.md`. Para cada um: o frontmatter vem do perfil, e o corpo vem de `core/roles/<papel>.md` (1D, sem o frontmatter neutro).
     - `name: harness-<papel>` e `description` do papel;
     - `model`: para um papel `pinned`, o ID completo de `models.pins.<papel>`. Sem pin, o alias de `models.tiers.<tier>.claude-code`. Um `pinned: true` sem pin no perfil → `fail`, "pin obrigatório para o verifier (D31)";
     - `effort` vem do papel;
     - para papéis `readonly`: `disallowedTools: Edit, Write, NotebookEdit, Agent`. O verifier mantém `Bash`, porque o S7 aceita resultado de execução como evidência. Para o implementer: `disallowedTools: Agent` (profundidade da Etapa 1 = L1);
     - um cabeçalho `<!-- gerado por harness render a partir de core/roles/<papel>.md; não edite -->`.
   - **Skills (D15).** `core/skills/<s>/` é copiado sem mudança para `.agents/skills/<s>/` (canônico) e para `.claude/skills/<s>/`. Na cópia do Claude Code entram os campos extras de `adapters/claude-code/skills.json` (`{ "<skill>": { "<campo>": <valor> } }`). Só `harness-*` é tocado.
   - **Tudo ou nada:** cada arquivo é gravado com `fsx.write_atomic`, e nada é gravado se alguma validação falhar antes.
2. **`harness hook <nome> --adapter claude-code`**: o fluxo de 3 passos de [hooks.md](../../contracts/hooks.md#fluxo).
   - `adapters/claude-code/translate.py`: nativo → `hook-event`. `projectDir` = `git rev-parse --show-toplevel` a partir do `cwd` do stdin, nunca `CLAUDE_PROJECT_DIR` (fatos §6). Caminhos `\` e absolutos viram relativos com `/`;
   - `core/hooks/<nome>.py:decide(event) -> dict` (`hook-result`). O resultado é validado contra o schema antes de ir para o passo 3;
   - passo 3: `allow`/`ask` → exit 0 e JSON nativo no stdout. `block` → exit 2, com `what — why — instead` no **stderr** e `{"decision":"block","reason":…}` no stdout;
   - **fail-closed** para o `stop_gate`: exceção, resultado inválido ou módulo ausente viram `block` com a mensagem "hook falhou: rode `harness doctor`; para encerrar, registre o blocker" (hooks.md, Falhas). Para os outros nomes, fail-open com aviso.
3. **`core/hooks/stop_gate.py` (S4).** Coleta as tasks `in-progress` sem `blocker` em `.harness/work/*/tasks.json`. Para cada uma, `evidence.check(evidence.latest())`. Qualquer código diferente de `fresh` → `block`, listando até 3 tasks: `what` = "<ID> em andamento sem gate verde na árvore atual (<code>)", `why` = "S4: não se encerra com vermelho (cap. 17)", `instead` = "rode `harness gate <ID>`; se não der para resolver, `harness task block <ID> --reason …`". Se tudo está fresco ou não há task em andamento → `allow`.
   - **Reentradas:** um contador por task em `.harness/runs/stop-gate.json` (o arquivo está nos `treeExcludes`), incrementado a cada `block` e zerado no `allow`. Na contagem `limits.stopReentries` (padrão 3), o `instead` passa a ser só o `task block`. O contador conta mesmo quando `stop.reentry` é falso, porque o Claude Code zera o dele a cada chamada de ferramenta (fatos §1).
   - `components.stopGate: false` → sempre `allow`.
4. **Probe dos fatos** que esta trilha usa (exigência do spike 0.7), feito à mão num repo descartável com o `claude` real e registrado em `docs/plan/etapa-1/1C-probe.md`, com a versão e o resultado de cada um: (a) exit 2 + stderr no `Stop` faz o agente continuar e recebe a razão; (b) `stop_hook_active` chega `true` na reentrada; (c) a forma do `Edit(...)` que bloqueia a ferramenta Edit em `.harness/work/X/tasks.json`; (d) `model` com ID completo no frontmatter é o modelo usado pelo sub-agent; (e) o AGENTS.md é lido sem CLAUDE.md. Se algum fato divergir → `contract-changes.md`, antes de depender dele.

**Fora:** `boundary_guard`, `post_edit`, `session_bootstrap` e `handoff_guard` (3S, 3C); Cursor e Codex (3C); compilação de `never`/`ask` (3S); `.harness/bin` e o lock (2B); o `doctor` checando `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` (3B, mas a 1I anota).

## Critério binário da trilha

- [ ] `pytest` verde.
- [ ] Cada par em `tests/fixtures/claude-code/*.native.json` → `translate` produz exatamente o `.neutral.json` correspondente (os 7 pares, Windows incluído).
- [ ] O `render` duas vezes seguidas: a segunda tem `changed == []`, e os arquivos ficam byte a byte iguais.
- [ ] Num `settings.json` com hooks e permissões do time: depois do render, toda chave e toda entrada original continuam presentes e na mesma ordem; o harness tem exatamente 1 handler `Stop`. JSON inválido → `fail`, sem escrita.
- [ ] Num AGENTS.md com conteúdo do time: o diff do render fica só entre os marcadores. Marcador órfão → `fail` com `arquivo:linha`.
- [ ] O `harness-verifier.md` gerado tem `model: <ID do pin>` e `disallowedTools` contendo `Edit` e `Agent`. Perfil com `pinned: true` sem pin → `fail`.
- [ ] A skill canônica em `.agents/skills/` tem só os campos portáveis (fatos §4); a cópia em `.claude/skills/` tem os extras do overlay.
- [ ] `stop_gate`: task em andamento com manifesto `fresh` → `allow`; com `stale-tree`, `not-pass` ou sem manifesto → `block` com `what`/`why`/`instead`; com blocker → `allow`; na 3ª reentrada, o `instead` contém `harness task block`.
- [ ] `harness hook stop_gate` com o `decide` levantando exceção → exit 2 e a mensagem de falha no stderr (fail-closed provado).
- [ ] Todo `hook-result` produzido nos testes passa no schema `hook-result`.
- [ ] `1C-probe.md` existe e registra (a)–(e) com a versão do Claude Code. Fato divergente = item em `contract-changes.md`.

## O que usa de stub

- **[tests/stubs/hook_stub.py](../../../tests/stubs/hook_stub.py)** para testar o passo 3 do adaptador (`allow`/`ask`/`block`) sem depender do `stop_gate`.
- **Evidência:** `stop_gate.decide(event, check=evidence.check)` recebe a função por parâmetro. Nos testes, um falso devolve `fresh`/`stale-tree`/… O código de produção importa `core.lib.evidence` (1A). Se o módulo não existir em produção, o `import` falha, e o fail-closed bloqueia. Isso é intencional até o merge.
- **Conteúdo da 1D** (`core/templates/AGENTS.md`, `agents-workflow.md`, `core/roles/*.md`, `core/skills/harness-execute/`): cópias mínimas em `tests/unit/render/data/`. O render lê os caminhos reais de `core/`, e a 1I confere com o conteúdo de verdade.
- **Perfil:** `core/schemas/examples/profile/valid-brownfield-python.json`.
